# 검토 기록

독립 검토자(Claude Opus 5.5 xhigh, 새 맥락, 파일 수정 금지)의 판정과 그에 따른 수정 흐름입니다. "중" 이상 결함이 하나라도 있으면 실패로 판정하고, 일꾼↔검토자 왕복은 작업당 최대 2회로 제한했습니다.

| 작업 | 범위 | 판정 흐름 | 실패로 이어진 핵심 지적 |
|---|---|---|---|
| Tool | KOBIS·TMDB·카카오 Tool 4종, 공통 규약 | 실패 → 수정 1 → 통과 | 주간 박스오피스의 실제 조회 기준일과 보고값 불일치(추정 표시 누락), Tool 출력 구조 미등록 |
| 이벤트·저장소 | 이벤트 버스, 로깅 Agent, SQLite | 실패 → 수정 1 → 통과 | 서버 재시작 후 같은 세션의 seq가 1로 돌아가 로그 상세 순서가 섞임 |
| 메인 Agent | LangGraph 6단계 그래프 | 실패 → 수정 1 → 통과 | 찾는 영화 제목이 어디에도 없을 때 사유를 "시간 조건"으로 잘못 안내 |
| API·화면 | FastAPI, 화면 3개 | 통과(하 지적 3건 후속 반영 → 통과) | — |
| 실제 실행 후 코드 | 실패 안내, 병렬화, 시각·날짜 규칙, 재시도, 캐시 | 실패 → 수정 1 → 통과 | 규칙 오탐("밤 12시"를 정오로, "내일 말고 토요일"에서 앞 날짜 채택), 실패 코드가 답변에 원문 그대로 노출 |
| 1차 문서 | 제출 문서 6종 | 실패 → Astra 호출 | 이용 조건 준수를 "적용"으로 과장, KOBIS 저장 관련 검토 누락 |
| 저장 경계 | Astra 지시 반영(로그·Memory·계획·샘플) | 실패 → 수정 1 → 통과 | 실제 API 시나리오 실행이 외부 추적(LangSmith)을 끄지 않아 KOBIS 결과가 외부로 나갈 수 있는 경로 |
| 최종 문서 | Astra 지시 반영 후 문서 | 실패 → 수정 → 실패 → 수정 → 실패(문구) → 사용자 승인 후 오케스트레이터 직접 수정 | 테스트 수 오기, 답변 원문 단락에 KOBIS 결과와 다른 출처가 섞임, 상한 도달 사유가 API 응답에서 누락 |
| 심화 F3020 | 이상 징후 판단 | 통과(하 지적 6건 후속 반영, 재검토 없음) | — |

## 해석

- **처음 제출한 구현은 대부분 한 번은 실패했습니다.** 실패 사유는 대부분 단위 테스트가 다루지 않은 경계 상황이었습니다. 재시작 후 순서, 모호한 자연어, 외부 서비스로 새는 경로가 그 예입니다. 검토자가 직접 탐침을 짜서 재현한 결과입니다.
- **같은 검증이 두 번 연속 실패한 경우는 없었습니다.** 그래서 Astra를 호출한 이유는 반복 실패가 아니라 명세 해석 충돌(조건 3) 한 번뿐이었습니다.
- **재검토를 거치지 않은 변경이 둘 있습니다.** 최종 문서의 마지막 문구 수정과 F3020 통과 후 반영한 하 지적입니다. 둘 다 테스트와 화면으로 확인했고, 이 문서에도 그 사실을 남겼습니다.
