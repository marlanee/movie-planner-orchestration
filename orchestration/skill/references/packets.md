# 양식 5종

모든 양식은 마크다운 파일로 `<repo>/.omc/pipeline/<task_id>/` 아래에 둔다. 칸이 비면 "없음"이라고 쓴다.

## 1. TASK PACKET (오케스트레이터 → 일꾼) — `task_packet.md`

```
# TASK PACKET
- task_id:
- 목표: (한두 문장)
- 관련 요구사항 ID: (예: F3002, F3003, NF3003)
- 관련 결정: (DECISIONS.md에서 필요한 줄만 옮김)
- 건드릴 파일: (경로 목록. 이 밖은 고치지 않음)
- 건드리지 말 파일:
- 구현 지시: (번호 목록)
- 완료 기준: (검증 가능한 문장으로)
- 검증 명령: (복사해 실행할 수 있는 명령)
- Astra 지시 반영: (ASTRA DIRECTIVE에서 옮긴 경우 issue_id와 지시 원문 요약, 아니면 없음)
- 수정 회차: (최초 0, 검토 실패 후 재지시 1·2)
- 이전 검토 지적: (수정 회차일 때만)
```

## 2. WORK RESULT (일꾼 → 오케스트레이터) — `work_result.md`

```
# WORK RESULT
- task_id:
- 변경 파일: (경로와 한 줄 요약)
- 구현 요약:
- 검증 실행: (명령 / 결과 요약 / 실행·미실행 구분)
- 완료 기준 대비: (기준별 충족·미충족)
- 이전 검토 지적 처리: (지적별 반영·부분 반영·미반영과 이유)
- 범위 밖 필요 사항:
- 미해결·위험:
```

## 3. REVIEW RESULT (검토자 → 오케스트레이터) — `review_result.md`

검토 요청 파일 `review_request.md`에는 task_id, 요구사항 ID, 완료 기준, 검증 명령, 변경 파일 목록(또는 `git diff` 범위)만 넣는다. 오케스트레이터의 설계 설명은 넣지 않는다.

```
# REVIEW RESULT
- task_id:
- 판정: 통과 / 실패 / 판정 불가
- 요구사항별:
  | ID | 판정 | 근거(실행 결과·코드 위치) | 근거 종류(실행/코드/추정) |
- 발견 사항: (ID·중요도(상/중/하)·위치·근거·영향·수정 제안)
- 실행한 검증: (명령과 결과)
- 일꾼과 갈린 지점: (있으면 Astra 호출 조건 2 후보)
```

## 4. ESCALATION PACKET (오케스트레이터 → Astra) — `escalation_packet.md`

일꾼의 대화 원문은 넣지 않는다. 사실과 결과만 정리한다.

```
# ESCALATION PACKET
- issue_id:
- 호출 조건: 1(같은 검증 2연속 실패) / 2(일꾼·검토자 1회 왕복 후 이견) / 3(명세·설계 해석)
- 이 issue의 Astra 호출 회차: 1 / 2
- 문제 정의:
- 관련 요구사항 ID와 원문 요지:
- 관련 결정(DECISIONS.md):
- 시도한 것과 결과: (시도별 변경 / 검증 명령 / 결과)
- 검토자 지적:
- 관련 코드 위치: (파일:줄)
- 오케스트레이터가 원하는 답의 형태: (예: 처리 방식 선택 + 구현 지시)
```

## 5. ASTRA DIRECTIVE (Astra → 오케스트레이터) — `astra_directive.md`

```
# ASTRA DIRECTIVE
- issue_id:
- 진단: (원인)
- 해결안: (일꾼이 그대로 따를 수 있는 번호 목록: 파일 / 바꿀 내용)
- 바뀌는 결정: (DECISIONS.md에 기록할 문장, 없으면 없음)
- 검증 방법: (명령과 기대 결과)
- 사용자 확인 필요: (사용자 결정을 바꿔야만 풀리는 경우 질문 문안, 아니면 없음)
- 확신도: 상/중/하 와 그 이유
```
